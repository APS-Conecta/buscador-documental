# S4 FRD: embedding profiles and hybrid search

## Goal
Users find documents by keywords (Exacta), by meaning (Por significado) or both (Mixta, reciprocal rank fusion k=60), with filters, four sort orders and stable paging, without ever seeing a document they cannot read. Administrators choose the embedding profile; the app never switches it by itself.

## Users
Every user (search); administrators (profile, preflight result, vector coverage).

## Decisions taken
| Topic | Decision | Source |
|---|---|---|
| Engine | Postgres FTS plus pgvector `halfvec`; permissions unchanged (stored principals prefilter, live recheck decides) | 00-scope, ADR-0001/0003 |
| Profiles | Auto-recommended by preflight, stored in an editable setting, changed only by an admin (`occ buscador:profile`), never auto-switched; a change re-embeds into a new `chunk_vec_<gen>` table | ADR-0004, 00-scope cuts |
| **Embedder (user, 2026-10-17)** | **First profile targets an Ollama endpoint.** `profiles.yaml` names the model; the app ships no model; query embedding uses the same endpoint. Preflight is independent of Ollama (it reports hardware and recommends, and works when Ollama is absent) | user answer |
| Modes | Exacta, Por significado, Mixta; semantic modes shown disabled with a progress note until vector coverage passes the S0 threshold and hybrid beats both single modes (A-QUAL-4) | 00-scope, open question 5 |
| **Filters (user)** | File type, date range, folder/path (a subtree the user can read) | user answer |
| Sort and paging | Relevance, newest, oldest, name; pages of 25/50/100 with keyset cursors; 1 000-result cap; results grouped per document with best page and snippet | PLAN S4 |
| Failure | Fallback to Exacta on embedding timeout or Ollama down, with a visible note | PLAN S4 |
| **Synonyms (user, supplied 2026-10-17)** | The user supplied a 1 000-entry Chilean APS dictionary of terms, acronyms and abbreviations in ten sections (institutions and network, information systems and law, family-health model and programmes, professions and units, cardiovascular/respiratory/chronic, women/child/adolescent, mental health and older people, clinical-record shorthand, laboratory and diagnostics, pharmacology). It is an acronym-to-expansion dictionary, not synonym groups. The mechanism ships as a static versioned file built from it. Open question 1 is closed | user message |
| Targets | keyword p95 < 1 s, hybrid p95 < 2 s at 1M-page equivalent | 00-scope |

## Constraints
- Docker only, compose project `bd-s1`, localhost only; Ollama is an external endpoint, tests use a stub embedder.
- Needs U0 accepted before any mode UI (S6); S4 delivers the API and occ, not screens.
- Erasure must cover `chunk_vec_<gen>` (erase_files already handles generation tables).
- The legal gate does not hold up S4.

## Open items (not blocking design)
- Which Ollama model for the first profile, and its dimension (research: S0 used multilingual-e5-small; confirm what Ollama serves and its Spanish quality on the gold set).
- Vector coverage threshold: take the number from S0 `acceptance.md`.
- The pasted dictionary exists only in the chat so far: the verbatim text must be saved into the repo as source data (proposed `buscador/data/aps-glosario-chile.md`) before design; research/design converts it to the versioned lookup file.
- Dictionary hygiene to decide in design: ambiguous keys (SS, FA, PCR, CD, HD, EA, CCR, CGR, TP, AM, OT, IRA, EC, DAS, ...) need a rule (expand only with context, or both senses); entries that are not abbreviations (e.g. numbers 170-176 phrases, drug classes) are weighted lower; LaTeX fragments (`$...$`) and parentheticals in values are stripped; clinical-record shorthand (section 8) matters for OCR text and the unaccent/case-insensitive match.
- Whether expansion applies at query time only (query `REM` also matches "Resumen Estadístico Mensual") or also at index time; decide in design with the gold set.
- Recheck cost for filtered and deeper-paged searches (A-PERF-2/5): research.
