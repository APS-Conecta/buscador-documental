# S3 FRD: events, reconciliation, scope and erasure

## Goal
Keep the index true to Nextcloud without anyone running a command: file and permission events flow through an outbox; a nightly reconciliation repairs whatever events missed; scope decides what may be indexed at all; `rag-excluded` and user deletion remove data for good; every action is audited without leaking document or query text. Closes the S1/S2 stubs: `IndexEraser` listener, `acl_dirty` processing, `purge-user`, the skipped-files reason table.

## Users
Administrators (scope, pause/resume, status, purge-user); every user (gets correct, current permission behaviour); counsel/DPIA owner (audit trail, notice).

## Decisions taken
| Topic | Decision | Source |
|---|---|---|
| Events | App listeners write `outbox` rows; a PHP job processes them; delete beats earlier events through `tombstone` | 01-architecture.md |
| Permission changes | NC marks `acl_dirty`; a PHP job recomputes principals and bumps `acl_ver`, ahead of backfill; backlog age exposed in `occ status` | 01-architecture.md |
| Reconciliation | Nightly manifest diff repairs missed events; per-file status visible | PLAN S3, A-OPS-3 |
| Scope default | `scope_mode = opt_in`; `all_readable` selectable only after counsel confirmation and a recorded DPIA; `rag-excluded` always wins and deletes existing index data | ADR-0006 |
| **Opt-in mechanism (user, 2026-10-17)** | **Admin-managed rules, automatic inside them:** (a) *subtree rule*: an administrator includes a folder once and everything under it (new files, new subfolders, moves inside it) is indexed automatically; (b) *groupfolder rule*: one rule "all team folders" also covers future team folders. Personal folders only through explicit folder rules. Nothing is indexed outside a rule. Rule changes are previewable and audited; managed on the admin page and with `occ` | user answers |
| Erasure | `rag-excluded` (file or ancestor) deletes chunks, vectors, pages, cache entries; user deletion erases owner rows with audit pseudonymisation; `occ purge-user` | A-SEC-3, A-SEC-6 |
| Grace period | Trash and old versions: not searchable, purged after 30 days | 00-scope.md (assumption, open question #4: counsel/user) |
| Audit retention | 90 days proposed | open question #7 (counsel) |
| Log hygiene | Zero document or query text in logs, errors or history; checked by a CI canary | A-SEC-5 |
| `occ` surface | `status, reindex, pause, resume, purge-user, doctor, profile, rotate-secret` (S3 delivers status, pause, resume, purge-user, reindex) | 00-scope.md cuts |
| First-run notice and pause | Backend: a notice-acknowledged setting and pause/resume; the screens are S6 | PLAN S3, S6 |

## Constraints
- Docker only, compose project `bd-s1`, 127.0.0.1 only.
- Tables owned by S3 (`outbox`, `tombstone`, `audit_log`, scope rules) separate from S2's tables; no change to the worker channel contract.
- The counsel/DPIA gate (A-SEC-7) is a release gate in S7 and a hard block on any real-data install; it does not hold up S4+.
- The RBAC adversarial matrix must cover circles, groupfolder ACL/deny, share expiry, download-disabled and multi-mount (exit criterion).

## Open items (not blocking design)
- 30-day grace period and 90-day audit retention are defaults pending counsel (open questions #4, #7).
- Whether Nextcloud 34 emits usable events for circles and groupfolder ACL changes: research (S1 notes found only the groupfolder-tag and mount-cache behaviour).
- Real-document validation of reconciliation cost at 1M files: S5/S7.
