# S5 research: what exists, what the plan asks for, what is missing

Local facts re-read in the code of main (3af0c70). Items needing a runtime answer are marked and answered by the phase that builds them.

## Plan text (PLAN.md S5)
Throttled, pausable, checkpointed backfill with ETA; keyword lane first, vector lane after; night window; health; `occ status|reindex|pause|resume|purge-user|doctor|profile|rotate-secret`; backup including page text; alert rules; runbooks (install, upgrade, rollback, rebuild, restore). Exit: ETA within a stated margin; pause/resume survives a restart; vector coverage % measured and exposed. Acceptance: A-OPS-1 (backfill ETA, pause/resume across restarts), A-OPS-2 (backup includes page text, restore rehearsal, measured rebuild time), A-OPS-4 (no outbound network during indexing and search).

## Gaps S5 closes
1. **ETA.** `status` shows queue counts, not a time. Needs a rate (completions per hour) and the remaining work per lane, and a stated margin.
2. **Throttle and night window.** Only fixed caps and the global pause. No way to say "embed only between 01:00 and 05:00" or "at most 2 files at a time" without editing SQL.
3. **Health.** No `doctor`; nothing says whether a worker is alive (no heartbeat record per worker, only per job), whether Ollama answers, whether the secret is set, whether cron mode is on.
4. **Secret rotation.** Changing `worker_secret` breaks the running worker at once; the architecture promised `occ` rotation.
5. **Alert rules.** None; `status --json` exists but nothing machine-friendly for monitoring and no rules.
6. **Backup and restore.** Nothing. The S3 research and the security doc require encrypted backups that include page text; a rehearsal with a measured time is an acceptance row.
7. **Egress.** A-OPS-4 is untested and false today (default bridge).
8. **Runbooks.** Install, upgrade, rollback, rebuild, restore, secret rotation, profile change: not written.

## Open technical questions (answered by building)
- `pg_dump -n aps_search` plus what the target needs first (roles `bd_owner`/`bd_worker`, extensions `unaccent`/`vector`, the Nextcloud DB user): to be rehearsed in a scratch database; the restore script must fail early and name what is missing.
- Whether an `internal: true` compose network blocks the worker's route to the internet while db, Nextcloud and the embedding stub stay reachable: tested by connecting to a public address from the worker.
- Nextcloud's own cron/background-job mode cannot be changed from the app; `doctor` only reads `backgroundjobs_mode`.
- Time-zone for the window: the SQL side needs an IANA name; PHP stores Nextcloud's default timezone at the moment the window is set.

## Not in S5
Dashboards, a metrics HTTP endpoint (the Prometheus text comes from an occ command that a node exporter textfile collector or cron can read), GPU profile automation, multi-node workers, the UI (S6), STRIDE review and load tests (S7).
