## 0. Findings that change the plan (read first)
1. **`gold.json` cannot score OCR.** `spikes/s0-harness/corpus/out/functional/gold.json` holds `n_files, n_narrow_files, queries[200], seed`; each query has `q`, `relevant_files`, `type`, `user` (retrieval gold set, generator `corpus/gen_gold.py:1`). OCR ground truth is `page_text` in `manifest.jsonl` (`corpus/gen_corpus.py:125-127`), which is not on disk now (only `gold.json` is under `corpus/out/functional/`); it is regenerated deterministically by seed (`corpus/determinism_check.sh`, README.md "byte-identical for a seed").
2. **The S1 worker uses the wrong OCR policy.** `worker/ocr.py:34-35` passes `--skip-text`; S0 measured that this keeps fake/garbage layers at CER 0.96-0.97 (`results-s0/m2.json` groups `fake_invisible/skip-text`, `fake_visible/skip-text`; `buscador/02-performance.md:33`). S2 must decide per page and use `--redo-ocr` (invisible layer) or `--force-ocr` (visible garbage).
3. **No code path yet records confidence.** `worker/main.py:87` writes `ocr_conf: None` and `source: "ocr"` for every page, although `page.ocr_conf real` is accepted (`app/lib/Migration/sql/002_functions.sql:116-118`). ocrmypdf's sidecar has no confidence (see 2.4), so confidence needs a Tesseract TSV pass or a different pipeline.
4. **Page and size caps are enforced after the expensive work.** `worker/main.py:80` checks `MAX_PAGES` after OCR has already run; `worker/ocr.py:8` has a flat 900 s timeout instead of the formula in `02-performance.md:49`. Only the parent `ocrmypdf` process is killed on timeout (`subprocess.run(timeout=)` at `worker/ocr.py:37`); its Tesseract/Ghostscript children are not in a killed process group (inference from subprocess semantics, UNVERIFIED on this image).
5. **The fixed reason enum limits A-SAFE outcomes.** `fail_job` only accepts `encrypted, too_large, corrupt, unsupported, ocr_failed, timeout, internal` (`002_functions.sql:137`). Bombs map to `too_large` or `corrupt`, a sandbox kill to `timeout`/`internal`. If the administrator should see "unsafe/sandbox violation" separately, S2 needs a migration (design question, section 4.6).
6. **The synthetic corpus does not exercise OSD.** Photos rotate only +-4 degrees (`corpus/gen_corpus.py:59`); no 90/180/270 page exists, so `--rotate-pages` is never tested on real orientation errors. Text is DejaVu Sans at 300 dpi from a Zipf word model (`gen_corpus.py:26`, `corpus/zipf.py`), so passing CER 2 % there is weak evidence (acceptance.md:22 already says "provisional until real documents").
7. `/root/aps-conecta/Databases/Legal/` holds six real Chilean law PDFs (Ley 19.628, 19.966, 20.584, 21.663, 21.719, Decreto 41) plus `convertir.py` with working Artículo/Capítulo regexes: real fixtures for chunking (section 3).

## 2. Per-page text-layer detection, OCR rotation/OSD/deskew, confidence

### 2.1 What S0 established (all `results-s0/m1.json`, `m2.json`, summary.md:65-82)
- `--skip-text`: native pages 0.39 s/page, CER 0.0000; mixed pages 6.67 s, CER 0.0004; fake invisible/visible layers kept, CER 0.96-0.97.
- `--redo-ocr`: fake invisible CER 0.0007 (9.6 s); fake visible CER 0.035 (fails on visible text in the docs, but worked on this corpus; the docs say fall back to `--force-ocr`, https://ocrmypdf.readthedocs.io/en/latest/cookbook.html).
- `--force-ocr`: scanned CER 0.001 (6 s/page); with `--deskew --rotate-pages` CER 0.0016 at 9.6 s/page.
- Photos without deskew/rotate: median CER 0.002 but max 0.898 (one of six failed); with them max 0.0018.
- No flag on a page with text: exit 6 `PriorOcrFoundError`, counted `skipped` (m1.json "native/no-flag"; exit code table below).
- `tessdata_fast` is the default (CER 0.11 % vs 0.07 % for best, 2.3 s vs 4.2 s per page, `02-performance.md:32`).

### 2.2 Per-page decision (recommended design input)
ocrmypdf's modes are document-wide, so a mixed PDF with a trusted native page and a fake-layer page needs a per-page policy. S0 already splits one page per PDF (`bench/extract_pages.py:228-231`). Proposed classification per page, computed in the sandbox with pypdf `extract_text()` plus pikepdf image coverage:
1. `native`: enough characters and plausible text -> keep the layer (source `layer`).
2. `image-only` (no usable text) -> `--force-ocr` or plain OCR (rasterised scan), source `ocr`.
3. `untrusted layer` (text present but implausible) -> `--redo-ocr` if the layer is invisible, `--force-ocr` if visible garbage.
Plausibility heuristics (all UNVERIFIED, to be calibrated on the S0 fake kinds, `corpus/gen_corpus.py:116-118`): characters per page, share of letters, U+FFFD / private-use / control characters, hit rate of a short Spanish+English stopword list, and a spot check (OCR a downscaled crop and compare). Limit: an invisible fake layer is indistinguishable from a good one by the layer alone; only comparison with an OCR sample detects it. Decide whether to pay that cost for every layered page (S0: +6 s/page) or only for pages failing the cheap tests; this is the main S2 design trade-off.
Budget for the plan: image-only share 46.8 %, 468 000 image-only pages per 1M-page equivalent (summary.md:85-89); mixed-policy pages cost ~9.5 s.

### 2.4 Confidence extraction
- ocrmypdf's sidecar is text only, with no confidence (cookbook, sidecar section; an hOCR renderer option in 14.0.1 is UNVERIFIED).
- Tesseract TSV: `tesseract img out -l spa+eng tsv` (or `-` for stdout) gives per-word position and confidence (https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html). That `conf = -1` for non-word (block/line) rows is UNVERIFIED in the fetched docs (from memory of the format: level, page_num, block_num, par_num, line_num, word_num, left, top, width, height, conf, text). Page confidence = mean of word `conf` over `level == 5` rows with conf >= 0 (own definition; weight by characters is an option).
- OSD: `--psm 0` is OSD-only (man page https://raw.githubusercontent.com/tesseract-ocr/tesseract/main/doc/tesseract.1.asc); output field names "Orientation confidence"/"Script confidence" UNVERIFIED.
- Options for the design step:
  - A. Keep ocrmypdf for text (proven in S0) and run a second `tesseract ... tsv` over the rendered page only to get the score: roughly doubles OCR cost (~+2.3-2.8 s/page with `fast`, `02-performance.md:32`).
  - B. Own pipeline for image-only pages: render with Ghostscript or extract the embedded image (pikepdf `PdfImage`, as S0 did, `bench/extract_pages.py:233`), `tesseract --psm 0` for OSD, rotate/deskew with Pillow, then a single `tesseract ... tsv` pass giving text and confidence. The worker never needs a searchable PDF, since it must not modify user files (`01-architecture.md:20`). Removes ocrmypdf for the product path (keep for eval comparisons), but re-implements deskew (Pillow has no deskew; ocrmypdf uses Leptonica via its own code, so deskew would need a new dependency, UNVERIFIED).
  - C. ocrmypdf `--output-type none --sidecar` for text plus TSV only on pages whose text is suspicious. Cheapest, but gives confidence only for those.
  Needs a threshold for "low confidence" flags (00-scope.md:30 "flag low confidence"; UI filter in `01-architecture.md` paging filters). Calibrate by correlating page confidence with per-page CER on the eval set (section 5).
- Store: `page.ocr_conf` (real), `page.source` (`layer`|`ocr`), `ocr_ver` string (`worker/ocr.py:20-24` builds it; include flags/policy and tessdata flavour so a policy change forces re-OCR via the idempotency key, `01-architecture.md:52`).

## 3. Structure-aware chunking

### 3.1 Requirements as written
- PLAN.md:22: structure-aware (Artículo/Capítulo), recursive 300-500 tokens, 10-15 % overlap, heading/page prefix, property tests.
- `01-architecture.md:64`: chunk size set for the **smallest max-token profile** (target 300-400 tokens **including** the heading/page prefix, counted conservatively), same chunks across profile generations (same `chunk_id`s), over-long input fails loudly (no silent truncation). e5-small max_len is 512 (`spikes/s0-harness/bench/embed.py:36`). So the hard cap is below 512 minus the special tokens; the 300-500 in PLAN.md is reconciled as target 300-400, hard max 500 (design to confirm).
- Contract limits: 2000 chunks, 20 000 characters per chunk, 10 000 pages per payload (`002_functions.sql:108-110`; `worker/chunk.py:8-9`). Current output shape `{page_no, ord, heading, text}` (`worker/chunk.py:39-45`); `chunk.TooManyChunks` -> `too_large` (`worker/main.py:84-85`). Current placeholder: character target 1000, no overlap, heading always None, doubles the target when over 2000 chunks (`worker/chunk.py:39-49`). The doubling must not coexist with a token cap; replace with a refusal.
- Token counting: use the `tokenizers` e5 `tokenizer.json` as S0 did (`bench/chunking.py:6-24` naive chunker at 350/35 tokens; `bench/embed.py:9-13`). The worker has no tokenizer today; ADR-0004 says bundles are pinned and checksummed with no runtime downloads (`adr/0004`:12-13), so the tokenizer file must come from the same bundle (design question: the worker image vs the model bundle).

### 3.2 Spanish legal structure detection
Reuse the proven regexes from `/root/aps-conecta/Databases/Legal/convertir.py:41-70` (verified by me):
- `RE_ARTICULO`: line start, `Artículo|ARTÍCULO` + number / word-ordinal (`primero`..`duodécimo`) / roman numeral, optional `º ° bis ter quáter ...`, and **mandatory trailing punctuation** `[.\-–]`, so cross-references inside a sentence ("el Artículo 93 de la Constitución...") do not match. Case-sensitive on purpose.
- `RE_ESTRUCTURA`: `TÍTULO|Capítulo|CAPÍTULO|Párrafo|PÁRRAFO|LIBRO|Disposiciones Transitorias|Artículos Transitorios`, at line start, without tolerating an opening quote (quoted text from other laws).
- Transitory articles restart numbering (`convertir.py:~377`, agent-reported), so heading identity must be the full path (e.g. "Artículos Transitorios > Artículo 1°"), not the article number alone.
- Known limit stated in the source: quoted structure of other laws is not detected.
- Heading prefix: build `"{Capítulo path} > {Artículo n} (p. N)"` and prepend to the chunk text for embedding while storing `heading` separately (the `chunk.heading` column exists, `01-architecture.md:30`). The prefix counts toward the token budget. Whether `tsv` is generated from `text` including the prefix is a design decision (affects ts_rank on headings).
- Non-legal documents (clinical protocols, minutes, spreadsheets): fall back to markdown `#` headings, docx heading styles (read from `w:pStyle` in the in-house reader), all-caps short lines (UNVERIFIED heuristic), then paragraphs.

### 3.3 Algorithm outline (recursive, as PLAN says)
1. Build an ordered list of blocks with `(page_no, heading_path, text)`; keep page numbers (a chunk keeps the page where it starts; `page_no` is single-valued in the schema).
2. Greedy pack blocks under the same heading to <= target tokens; never merge across an Artículo/Capítulo boundary.
3. A block above the cap is split recursively: paragraph -> line -> sentence (Spanish sentence boundary after `.?!` followed by capital; beware "Art.", "N°", "Sr.", "Dr.", numbers like `21.719`; `21.719` appears in the gold-set tokenisation tests, `01-architecture.md:58`) -> whitespace -> hard token split for unbroken strings.
4. Overlap 10-15 % of the target (30-60 tokens at 400): copy the tail of the previous chunk of the *same section*, aligned to a sentence boundary when possible; none across a section boundary (decision to confirm: overlap across headings would blur citations).
5. Tables from xlsx/docx: one chunk per row-group with the header row repeated (design question).
6. Output dedupe interplay: ADR-0005 copies rows when `(content_hash, ocr_ver, chunker_ver)` match (`adr/0005`:10), so any change to chunking must bump `CHUNKER_VER` (`worker/chunk.py:7`).

### 3.4 Property tests with Hypothesis
Docs facts (https://hypothesis.readthedocs.io/en/latest/reference/api.html, `/stateful.html`, `/reference/strategies.html`): default `max_examples` 100, default `deadline` 200 ms (None on CI), `derandomize=False` (True on CI), database `.hypothesis/examples`; profiles via `settings.register_profile` / `load_profile`; built-in `ci` profile when `CI` is set sets `derandomize=True, deadline=None, database=None`; `@composite` strategies take `draw`; `st.text(alphabet, min_size, max_size)` excludes surrogates by default. Stateful tests (`RuleBasedStateMachine`) are not needed here.
Strategy: `@st.composite` generating a document = list of pages, each a list of blocks drawn from {plain paragraph (Spanish words with accents/ñ, NFC and NFD), `Artículo N°.` line (all ordinal/roman/bis forms), `Capítulo` line, markdown heading, very long unbroken token, CRLF, tabs, NUL, empty page}. Properties (hard asserts unless marked):
1. **Coverage:** concatenating chunk texts with the overlap removed reproduces the normalised input (whitespace-insensitive), nothing dropped, no text invented.
2. **Token bounds:** every chunk (prefix included) <= hard max with the production tokenizer or a deterministic stand-in (whitespace/sub-word fake) in fast tests; real `tokenizer.json` in a slower marked test.
3. **Target:** all chunks but the last of each section reach >= a floor (e.g. 50 % of target) unless followed by a section boundary.
4. **Overlap:** consecutive chunks of the same section overlap by 10-15 % of the target (+- one sentence), and never across a section boundary.
5. **Structure:** a chunk contains at most one Artículo header, always as its first line; `heading` equals the nearest preceding structure path; transitory restarts do not collide.
6. **Order and ids:** `ord` is 0..n-1 contiguous; `page_no` non-decreasing and within [1, n_pages]; blank pages produce no chunk; no empty or whitespace-only chunk.
7. **Caps:** <= 2000 chunks and <= 20 000 characters per chunk, else `TooManyChunks` (never truncation); NUL removed (`worker/chunk.py:16-17`).
8. **Determinism / idempotence:** same input -> identical output; chunking already-chunked text is a no-op in boundaries.
9. **Never splits a sentence mid-token / a number such as `21.719`, a RUT or a folio** (regression examples via `@example`).
Settings: register a `ci` profile (`derandomize=True`, `deadline=None`, `max_examples=200+`) and keep failures as `@example`s; existing example-based tests are in `worker/tests/test_chunk.py` (plain pytest, 6 tests; the first two assert the placeholder behaviour and will be replaced). `make test` runs in the image (`worker/Makefile`), so add `hypothesis` to the image. Fixtures: the six real law PDFs in `/root/aps-conecta/Databases/Legal/` (convertir.py checks article counts, e.g. Ley 19.628 = 24 permanent + 3 transitory, a ready-made oracle for property 5); redistribution of those PDFs in this repo is not checked (UNVERIFIED), generate synthetic ones instead and use the real ones only locally. No sibling has property tests (agent search).

## 4. Sandbox and caps for hostile files (A-SAFE-2, A-SAFE-3, A-SAFE-1)

### 4.1 Required design and current state
- Required (`01-architecture.md:75-76`, `04-security-privacy.md:20`): supervisor holds secrets and network; each parser/OCR step is a child with scrubbed env, own network namespace (`unshare -n`), rlimits, explicit seccomp profile, cgroup v2 CPU/memory/PID limits, read-only rootfs + tmpfs, non-root, per-file timeout, no Docker socket. S2 proves it with tests: parser cannot read worker env or reach Postgres/app.
- Current: the whole worker is one process tree with DB and HMAC secrets in its environment (`compose.yaml:68-72`), `mem_limit: 2g` only (`compose.yaml:62`), uid 10001 (`worker/Dockerfile:13-14`). No sibling implements `unshare`, seccomp, `setrlimit`, `pids_limit` or `no-new-privileges` (agent search); `read_only`/`tmpfs`/`cap_drop` appear only in the AIO manifest (`/root/aps-conecta/instalador/manual-install/latest.yml:61-68`).

### 4.2 Mechanisms and their documented behaviour
- Docker run: `--read-only` (volumes stay writable), `--tmpfs`, `--memory`, `--pids-limit`, `no-new-privileges` (https://docs.docker.com/reference/cli/docker/container/run/). `--network none` and `--cap-drop ALL` are standard but not shown on the fetched page (UNVERIFIED there).
- Default seccomp is an allowlist blocking ~44 of 300+ syscalls (`mount`, `ptrace`, `bpf`, `setns`, `userfaultfd`, `io_uring_*`); custom profile with `--security-opt seccomp=profile.json` (https://docs.docker.com/engine/security/seccomp/).
- `unshare --net` gives a new empty network namespace; `--map-root-user` allows unprivileged setup (https://man7.org/linux/man-pages/man1/unshare.1.html). Whether `unshare` works inside the default-seccomp, non-privileged worker container is **UNVERIFIED** (my recollection: the default profile denies `unshare`/`CLONE_NEWUSER` without `CAP_SYS_ADMIN`; this must be tested first, because it decides the architecture).
- `resource.setrlimit` (https://docs.python.org/3/library/resource.html): `RLIMIT_AS`, `RLIMIT_CPU` (SIGXCPU), `RLIMIT_FSIZE`, `RLIMIT_NOFILE`; soft/hard; non-root cannot raise the hard limit. Behaviour on hitting limits is from `getrlimit(2)` (not fetched, UNVERIFIED).
- Ghostscript `-dSAFER` is the default since 9.50, `-dNOSAFER` would disable it (https://ghostscript.readthedocs.io/en/latest/use.html, agent URL `/Use.html`); ocrmypdf calls Ghostscript itself, so check that the image's Ghostscript is >= 9.50 (bookworm ships 10.x, UNVERIFIED).
- Pillow: warns when pixels > `MAX_IMAGE_PIXELS`, raises `DecompressionBombError` above 2x; `None` disables (https://pillow.readthedocs.io/en/stable/reference/Image.html). The page gives no default; `02-performance.md:47` states 89 MP and a 50 MP cap. Set `Image.MAX_IMAGE_PIXELS = 50e6` explicitly and promote `DecompressionBombWarning` to an error.
- OCRmyPDF's own untrusted-input guidance: its security page returned 404 (UNVERIFIED). Its batch docs say malformed PDFs are repaired before parsing (https://ocrmypdf.readthedocs.io/en/latest/batch.html).

### 4.3 Architecture options for the design step
- **Option 1 (as written):** one worker container, supervisor spawns `unshare -n --map-root-user` children with `preexec_fn` rlimits and `start_new_session=True` so the whole group can be killed. Needs seccomp relaxation for `unshare` (weakens the container) or `--cap-add SYS_ADMIN` (not acceptable). Test first.
- **Option 2 (recommended to evaluate):** two compose services: `worker` (supervisor: DB, HMAC, network, no parsing) and `parser` (`network_mode: none`, `read_only: true`, `tmpfs`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges, seccomp=<custom>]`, `pids_limit`, `mem_limit`, `cpus`, non-root, no secrets in env), exchanging the input file and result JSON over a shared tmpfs volume or a unix socket (works with `network_mode: none`). This satisfies "parser cannot read worker env or reach Postgres" structurally, without `unshare`, and without mounting the Docker socket. Cost: per-job IPC and deployment of two containers on customer boxes; compose-level limits are the cgroup v2 limits required by `01-architecture.md:75` (inference: Docker uses cgroups, v2 on this host is UNVERIFIED).
- Either way: scrubbed env, and a sandbox self-test endpoint used by the A-SAFE-2 tests (`env` readable? `getent hosts db` fails? `connect(5432)` fails? write outside tmpfs fails?).
- Kill whole process groups on timeout (finding 4); per-file timeout formula `min(3600, 12 x pages + 60)` and lease `timeout + 60` renewed after each page (`02-performance.md:49-50`); `Heartbeat` exists (`worker/main.py:35-51`).

### 4.4 Caps (values: `02-performance.md:45-53`) and where to enforce
| Cap | Value | Enforcement point (proposal) |
|---|---|---|
| File size | 250 MB | before download from `meta.size` (`worker/main.py:23,64`) and while streaming (the stream is hashed, count bytes) |
| Pages | 300 | **before OCR**, from pypdf/pikepdf page count (fix finding 4); also `/Pages` tree cycles/huge counts must be caught by the parser limit, not by trust |
| Pixels | 50 MP/page | Pillow limit as above; pikepdf image `Width x Height` read before rasterising; a PDF page with huge MediaBox rasterised by Ghostscript is a pixel bomb with no image (`--max-image-mpixels` UNVERIFIED; also cap the rasterisation DPI/size when rendering) |
| OCR per page | 180 s | `--tesseract-timeout 180` |
| Per file | min(3600, 12 x pages + 60) | supervisor clock + process-group kill |
| Zip ratio / total | 100:1, 1 GB, **not measured in S0** | S2 measures; apply to docx/xlsx/pptx/odt |
| xlsx cells | 1 000 000, **not measured in S0** | S2 measures extraction time; use `calculate_dimension()`; do not trust declared dimensions |
Zip handling: the sibling precedent (`/root/aps-conecta/IntraVox/lib/Service/Import/SafeZipExtractor.php:38-44,185-211`) checks declared sizes in the central directory (entry 100 MB, total 500 MB, 10 000 entries) and also caps actual output, rejects `..` and symlinks (`:138-140`); it has **no ratio check**. For Python: sum `ZipInfo.file_size` and entry count before reading, compute ratio from `compress_size`, then read each member through a counting wrapper that aborts at the cap, because declared sizes can lie. Also bound XML parse size and depth with `defusedxml`.

### 4.5 Hostile-file corpus for the tests (generate at test time, never commit binaries)
- zip bomb docx/xlsx/odt (small file, huge declared or real uncompressed size; nested zips); XML entity expansion ("billion laughs", quadratic blowup) in `document.xml`/`sheet1.xml`.
- xlsx declaring `A1:XFD1048576` with few cells; xlsx with 1M+ cells.
- pixel bomb: PNG/TIFF header declaring 60 000 x 60 000 with tiny data; PDF with an enormous MediaBox; PDF with a page-tree loop or 100 000 empty pages.
- encrypted PDF (user password); owner-password-only PDF (policy case); OOXML encrypted (a CFB/OLE container, magic `D0 CF 11 E0`, not a zip: from knowledge of MS-OFFCRYPTO, UNVERIFIED here); ODF with `manifest:encryption-data` (UNVERIFIED); NC-reported `meta.encrypted` (server-side/E2EE) is already handled (`worker/main.py:60-61`).
- malformed: truncated PDF/zip, wrong extension vs `meta.mime`, 0-byte file, a PDF that makes Tesseract hang (needs a timeout test with a fake slow tesseract on PATH).
- sandbox escape probes (section 4.3 self-test).
Expected results: each ends `text_state = skipped` with a reason from the enum, never `indexed`, never a crashed worker; the lease is not left to expire (`fail_job` called). Mapping proposal: size/zip/pixel/page/cell caps -> `too_large`; encrypted -> `encrypted`; parse errors -> `corrupt`; unknown mime -> `unsupported`; timeout/kill -> `timeout`; tool crash -> `ocr_failed` (retryable) or `internal`. `fail_job(..., retryable=False)` sets `skipped` immediately (`002_functions.sql:129-150`, `worker/main.py:113-120`); retry/backoff for `ocr_failed` and `timeout` is design-owned (attempt limit in `job.attempts`, `01-architecture.md:28`).

## 5. Measuring gold CER/WER (A-QUAL-1: CER <= 2 %, WER <= 5 %, `acceptance.md:22`)
Facts: `make eval-ocr` is TBD-S2 (acceptance.md:22). S0 baseline: m2 computes CER/WER with `rapidfuzz.distance.Levenshtein` on whitespace-normalised characters and word lists, median/max per group, reading the output PDF's text layer via pypdf (`bench/m2_cer.py:19-31,33-48`); results: scanned CER 0.07-0.16 %, WER 0.5-1.1 %; the only failure was a photo without deskew/rotate (CER 0.898).
Proposed method:
1. **Truth:** regenerate the corpus by seed (`make corpus`, `corpus/gen_corpus.py --seed`; same seed -> same bytes) and read `manifest.jsonl` `page_text`/`kind`/`image_only` (`gen_corpus.py:122-127`); do not use `gold.json` (retrieval only). Keep a committed small manifest of truth for CI if the generator is too slow (6 003 pages took ~7 min, README), e.g. a stratified sample like S0's `extract_pages.py` (`N = scanned 8, mixed 6, fake_visible 6, fake_invisible 6, photo 6, native 4`, line 213).
2. **System under test:** the worker's real `extract` function on each file, not a direct ocrmypdf call, so the policy (section 2.2) is what is graded. Compare per-page text (not the PDF text layer as S0 did).
3. **Normalisation (state it in the report):** Unicode NFC; collapse whitespace; case and accents kept (accent errors matter for Spanish search, although `spanish_unaccent` hides them at query time, `01-architecture.md:39`); no hyphenation repair.
4. **Metrics:** CER = Levenshtein(chars)/len(ref chars) and WER = Levenshtein(word lists)/len(ref words) (rapidfuzz MIT; `jiwer` is an alternative, not checked). Report pooled (sum of edits / sum of reference length) as the gate value, plus per-kind median, p95 and max, and the count of catastrophic pages (CER > 0.5). A pooled mean hides the S0 photo failure, so also fail if any page has CER > 0.5.
5. **Gate:** pooled CER <= 2 % and WER <= 5 % over image-only pages (scanned, photo, fake layers); native pages must be ~0 (S0: 0.0000). Show the numbers per tessdata flavour; `fast` is the default.
6. **Harder variants (to avoid a vacuous pass):** rotations 90/180/270, skew beyond 4 degrees, 150 and 200 dpi, stronger JPEG compression/noise, serif fonts, a table page, and a few real Spanish pages (public-domain scans or rendered law text from `/root/aps-conecta/Databases/Legal/convertir.py` output, `RE_ARTICULO` etc.; licensing of the PDFs UNVERIFIED). Real documents remain open question #2 (open-questions.md:7), so keep the A-QUAL-1 value labelled provisional.
7. **Confidence calibration:** for each page record (ocr_conf, CER) and choose the low-confidence threshold at a stated precision; report correlation; the eval output feeds the "low confidence" flag.
8. **Reproducibility:** pin versions in the report header like `results-s0/versions.json` (tesseract, ocrmypdf, tessdata sha256, rapidfuzz); results JSON with host load as S0 does (`bench/lib.py` write_result, used at `m2_cer.py:14`); run inside Docker only (CLAUDE.md "Nothing runs outside Docker"). `make eval-ocr` target should live in `worker/Makefile` or the harness and reuse `spikes/s0-harness` generators; dependency on the throwaway harness (README: "Not product code") means copying the small generator subset or promoting it, a design decision.
