## 5. Recheck design inputs (A-PERF-3, open item #11)
- S0 numbers: naive 760-820 ms, per-folder cache 330-405 ms, FS setup alone ~100-160 ms (`buscador/02-performance.md:16`, `results-s0/m9.json`). Targets conflict in the docs: 300 ms/50 hits (A-PERF-3, ADR-0003) vs 150 ms/~20 docs (`02-performance.md:12`).
- `Folder::getById` -> `Root::getByIdInPath`: one `IUserMountCache::getMountsForFileId` query + one cache-entry fetch per id, and may trigger mount setup: `$R/lib/private/Files/Node/Folder.php:330-332`, `$R/lib/private/Files/Node/Root.php:407-495`. `IUserMountCache` has no bulk file-id method: `$R/lib/public/Files/Config/IUserMountCache.php:48-67`. Public doc says use `getById`, not `getFirstNodeById`, for accuracy: `$R/lib/public/Files/Folder.php:150-177`.
- Never read `oc_filecache.permissions` directly: it bypasses groupfolders ACL and shares (inference).
- Alternative: `$userFolder->search(SearchQuery)` is how core `FilesSearchProvider` gets ACL-filtered results with no recheck: `$R/apps/files/lib/Search/FilesSearchProvider.php:110-142`. Whether a search constrained to candidate file ids beats ~50 `getById` calls: UNVERIFIED, candidate for the S1 benchmark.
- Groupfolders ACL lives in the app tarball `/root/aps-conecta/gestion/provisioning/apps/groupfolders/groupfolders-22.0.6.tar.gz` (not bundled in the NC image): `ACLManager::getRelevantPaths` walks all ancestors (`:114-130`), `getRulesByFileIds` is a bulk fetch (`:87-105`), `preloadRulesForFolder` only warms cache (`:267-273`). Rules can sit on the file itself, so parent-only batching is unsafe; classes are app-internal, not OCP API.
- Shares: `IShare::canDownload()` false when read bit missing or `permissions.download` attribute false (`$R/lib/private/Share20/Share.php:660-675`); expiry enforced on share load (`$R/lib/private/Share20/Manager.php:1414`). How a recipient's share mask is applied through `getById`, and circles membership: UNVERIFIED.
- Tag in bulk: `ISystemTagObjectMapper::getTagIdsForObjects($ids, 'files')` is one chunked `IN` query (`$R/lib/private/SystemTag/SystemTagObjectMapper.php:36-58`); `haveTag` returns one boolean only (`:237`). Object type `'files'` assumed. Whether tag visibility restrictions apply to the mapper: UNVERIFIED. Ancestor check needs the parent chain per hit; a per-request folder cache is where S0's 330-405 ms came from.
- Defects in the S0 probe vs the spec (`m9_isreadable.php:53`): takes `nodes[0]` not any readable node; no expiry check; download-disabled share is counted but still listed. The measured 330-405 ms therefore excludes some required work.

## 7. Implications for design
1. 2. S1 migrations need raw SQL for extension, text-search config, GIN and a restricted worker role; verify the NC DB user's privileges early.
3. S1 needs a synchronous erase path for `rag-excluded` and a defined payload schema for contract v1.
4. Resolve open item #11 with measurements before S1 exits; propose a waiver ADR only if the corrected probe cannot reach 300 ms.
5. A new `bd-` compose project with CI-sized resource limits; `make test-rbac` canary target.
