# S6 research: sibling-app conventions and Nextcloud 34 facts (Explore agent over /root/aps-conecta and the NC 34.0.4 image; claims cite file:line in the agent's report, summarised here)

## Build and layout conventions (siblings)
- Vue `^3.5`, `@nextcloud/vue` 9.x with **subpath imports only**; farmacia/estadistica/territorio use webpack + `@nextcloud/webpack-vue-config`, **epidemiologia uses Vite 7 + `@nextcloud/vite-config`** and cut its bundle from 1.08 MB to 359 KB by never importing from the `@nextcloud/vue` barrel. Node `^20 || ^22 || ^24`.
- The built `js/` is **committed** ("the bundle is the deployment") and a smoke step checks it matches `src/`. Page controller: `#[NoAdminRequired] #[NoCSRFRequired]` on `index`, `IInitialState::provideInitialState`, `Util::addScript(APP_ID, APP_ID.'-main')`, template with the `.aps-mount-loading` fragment; nav entry via `<navigation><route>` in `info.xml`.
- API client: thin `api.js` over `@nextcloud/axios` + `generateUrl`; server refusals are `422 {message}`; logs carry a label and the status, never the body.
- `aps-common` is a vendored subtree synced by `make aps-sync` (JS `fold()`/`textMatches()` mirror PHP `Text::fold` except whitespace collapsing).
- Tests: vitest 4 + `@vue/test-utils` + jsdom (`ssr.noExternal: [/@nextcloud\/vue/]`), Playwright on the host for layout at 360, 768 and 1366 px against a live instance. **No sibling has automated axe and none has a bundle budget**: both are new work. No Playwright image exists in the org.
- Theme rules: variables only (server variables live on `body`, `:root` is inert), `--color-text-error` for error text, no own `@font-face`, `prefers-contrast: more` handled once by the theme, light only.

## Nextcloud 34.0.4 facts
- **Unified search:** `OCP\Search\IProvider` (`getId`, `getName`, `getOrder($route, $params)` where `null` hides it, `search(IUser, ISearchQuery)`); results `SearchResult::complete/paginated` of `SearchResultEntry(thumbnailUrl, title, subline, resourceUrl, icon)`; registered with `registerSearchProvider`; the limit comes from `ISearchQuery::getLimit()`.
- **Files sidebar tab (legacy `OCA.Files.Sidebar` is gone):** `getSidebar().registerTab({id, order, displayName, iconSvgInline, tagName, enabled?, onInit?})` from `@nextcloud/files`; the tab is a custom element defined in `onInit`; PHP side listens to `OCA\Files\Event\LoadSidebar` and adds the script. Unverified: the props the sidebar sets on the element and the exact wrapping.
- **Opening at a page:** `/f/{fileid}` → `/apps/files/files/{id}?dir=…&openfile=true`; the PDF viewer is an iframe to `/apps/files_pdfviewer/?file=…` and the outer `#page=N` is **not forwarded**. A same-origin `PDFViewerApplication.page = N` after load is plausible but untested: a spike must decide and the fallback is "open the file, show the page number".
- **Admin settings:** `ISettings`/`IDelegatedSettings` + section registered in `info.xml`, template mount point, state through `IInitialState` / `loadState`.

## What the UI needs from the backend that does not exist yet
1. Hit fields the mockup shows: path, modified date, owner display name, "lectura incierta" flag.
2. Filters in the guidelines that S4 did not build: Propiedad (Mis archivos / Compartidos conmigo) and "Solo con lectura incierta".
3. Page and admin endpoints (initial state, status/overview, pause/resume, included folders, skipped files with retry, notice acknowledgement).
4. The unified-search provider (keyword only, top 5).
5. A "Texto reconocido" endpoint for the Files tab with its own permission guard and a rate-limited "Volver a leer".

## Decisions the blueprint takes
Vite + `@nextcloud/vite-config`, three entries (`main`, `admin`, `files-tab`), committed `js/`, a size gate on the initial `main` chunk (250 KB gzip), vitest + jsdom + axe-core for components, a pinned Playwright image against the live stack for keyboard path, 360 px and axe in a real browser.
