## 2. pgvector (open question #9)
- `hnsw.iterative_scan` was added in **0.8.0** (released 2024-10-30). Values `off | strict_order | relaxed_order`; default off is implied, not stated. Related: `hnsw.max_scan_tuples` default 20,000, `hnsw.scan_mem_multiplier` default 1, `hnsw.ef_search` default 40. https://raw.githubusercontent.com/pgvector/pgvector/master/CHANGELOG.md, https://raw.githubusercontent.com/pgvector/pgvector/master/README.md. **Verified: the >= 0.8 floor in the plan is correct.**
- Filtering is applied after the ANN scan; with 10% match and ef_search=40 about 4 rows survive. Iterative scan is the fix (README, Filtering). Narrow-ACL alternatives: partial index or partitioning (README). Which is best here: UNVERIFIED, benchmark in S0 (this is the A-QUAL-3 narrow-vs-200-group-admin test).
- `relaxed_order` returns slightly out-of-order rows; README fix is a `MATERIALIZED` CTE re-sorted with `ORDER BY distance + 0` (needed on PG17+). RRF uses rank, so use `strict_order` or the re-sort for the vector leg (inference, UNVERIFIED).
- `max_scan_tuples` caps the scan, so a very restrictive ACL can return fewer than LIMIT rows (implied, not stated). Record the short-result rate in S0.
- Images: Docker Hub has `0.8.7-pg16/-pg17` (+ `-bookworm`, `-trixie`), dated 2026-10-01. Pin the full tag, e.g. `pgvector/pgvector:0.8.7-pg17-bookworm`. Floating `pg16` tag not checked. https://hub.docker.com/v2/repositories/pgvector/pgvector/tags?name=0.8
- Spanish FTS: `unaccent` chained before the stemmer in a copied text-search config (docs example is French): https://www.postgresql.org/docs/current/unaccent.html. GIN is the preferred tsvector index: https://www.postgresql.org/docs/current/textsearch-indexes.html. `ts_rank` "can be I/O bound" on many matches: https://www.postgresql.org/docs/current/textsearch-controls.html. GIN pending list slows reads; consider `fastupdate=off` or higher `gin_pending_list_limit`: https://www.postgresql.org/docs/current/gin.html. pg_trgm is a fuzzy supplement, not a tsvector replacement: https://www.postgresql.org/docs/current/pgtrgm.html.
- UNVERIFIED: p95 for keyword search at ~1M pages (docs give no figures). That is exactly A-PERF-1 and the ADR-0001 trigger; S0 must measure. Mitigation to test: ACL filter and top-N before ranking.

## 3. OCR (open question #9)
- Tesseract per-page seconds at 300 dpi: **UNVERIFIED, no usable published figure.** Measure in S0. Weak data points: Tesseract 4.1.1 one invoice 14.4 s vs 12.6 s with `OMP_THREAD_LIMIT=1` (https://lab.nexedi.cn/seb/erp5/-/commit/d74981c37f5d619d8b8555ce7dd6605c89ab5e80); k2pdfopt 5.3.3 about 245 s single vs 175 s at 4 threads, page count unknown (https://www.willus.com/mingw/gcc1320/k2pdfopt_v255_benchmark_table.pdf).
- FAQ advises one single-threaded process per core for batches; OCRmyPDF sets `OMP_THREAD_LIMIT` itself if unset: https://tesseract-ocr.github.io/tessdoc/FAQ.html, https://ocrmypdf.readthedocs.io/en/latest/advanced.html. Plan: 8 workers x `OMP_THREAD_LIMIT=1`.
- `tessdata_fast` vs `tessdata_best`: relative claims only, no numbers; Spanish accuracy delta UNVERIFIED (https://tesseract-ocr.github.io/tessdoc/Data-Files.html). Measure CER/WER on both.
- OCRmyPDF flags (https://ocrmypdf.readthedocs.io/en/latest/cookbook.html, .../advanced.html, .../optimizer.html):
  - `--skip-text`: copies pages that have text unchanged. `--redo-ocr`: strips invisible OCR text and re-OCRs; fails on visible text, then use `--force-ocr`. `--force-ocr`: rasterizes and discards text layer.
  - `--deskew`, `--rotate-pages`, `--sidecar FILE` (omits pages that had text or were skipped), `--output-type pdf|pdfa|auto|none` (`none` with sidecar), `--tesseract-timeout` default 180 s, `--optimize 0`.
  - **Fake text layer**: invisible layer -> `--redo-ocr`; visible/garbage -> `--force-ocr`. Detecting it is our job (S2 per-page text-layer check).
  - `--jobs`: UNVERIFIED, check `--help` of the installed version.
- Exit codes (source, https://raw.githubusercontent.com/ocrmypdf/OCRmyPDF/main/src/ocrmypdf/exceptions.py): 0 ok, 2 input, 3 missing dep, 6 prior OCR found, 7 child process, 8 encrypted PDF, 10 PDF/A failed. Default message for text pages: "page already has text! (use --force-ocr to force OCR)" (https://ocrmypdf.readthedocs.io/en/latest/errors.html). Map 6 and 8 to `skipped` states. Password-protected handling UNVERIFIED.
- Packages: Debian stable `tesseract-ocr-spa` 1:4.1.0-2 (https://packages.debian.org/stable/tesseract-ocr-spa), fast/best flavour UNVERIFIED. Debian stable `ocrmypdf` 16.7.0, testing 17.10.0, upstream 17.13.0 (https://tracker.debian.org/pkg/ocrmypdf). Legacy flags work on all; `--mode` is 17.x only (inference). Image `jbarlow83/ocrmypdf-alpine` bundles spa (https://ocrmypdf.readthedocs.io/en/latest/docker.html); its Tesseract version UNVERIFIED. Pin the version used and record it in `capacity-sheet.md`.
