## Defects fixed in code
Determinism check compared sizes, not bytes (now sha256 of text, vectors and ACL rows); raw Tesseract exit codes and truncated model downloads were not checked and every non-zero ocrmypdf code counted as "skipped" (now fatal unless 6/8/timeout, atomic downloads); the m9 outcome guard compared only the first run and no expected counts (now every run against the fixture); m10 aborted on one timeout or an empty class (now censored, partial results written); gold-set generation could loop forever; m7 assumed 3M rows; the host-load docstring promised more than it records; tool versions (Python libs, Tesseract model hashes) were not recorded (now in `results/versions.json`).

## Not a defect (checked)
The m7 vector leg was suspected of not using HNSW for the narrow user: EXPLAIN shows an HNSW index scan with a nested loop to `file_acl` for both users and both iterative modes.

## Accepted or deferred
Disk check looks at the bind-mount filesystem, not the Docker volume (same filesystem on this box; README states the requirement). Host load is sampled at write time only. Python and apt pins are recorded, not enforced. `validate.py` P7 re-reads the aggregated result. These cost little and do not change a conclusion.
