# S5 review (diff auditor and security reviewer; claims re-checked before fixing)

Two independent read-only reviewers; their output was treated as claims. Everything fixed was reproduced or read in the code first and fixed test-first. A claim I verified myself while fixing: Nextcloud's own app-config cache lasts 3 seconds in the web process (`OC\AppConfig::LOCAL_CACHE_TTL`), which is why a rotation takes effect within seconds and why the live test waits for it.

| Sev | Finding | Fix | Proof |

## Accepted or deferred
| Item | Why |
|---|---|
| AES-CBC does not authenticate the backup; the checksum is unkeyed | The tooling available everywhere (openssl enc) has no AEAD mode. Mitigated by a restore that runs without superuser rights, a mandatory checksum, and the documented rule to restore only your own backups from storage others cannot write. A keyed MAC or `age` can replace it when the dependency is acceptable. |
| The ETA assumes continuous work and does not subtract the closed hours of a window that will close again before the queue empties | The CLI says "about"; it is correct within the open window and says when it opens |
| A worker holds the database credentials and can take the shared advisory lock `claim_job` uses, blocking all claims (pre-existing, S1) | The worker role is trusted with availability; S7 STRIDE review decides whether to give the lock a private key space |
| The expired previous secret stays stored until the next rotation | Rejected at validation (expiry is checked); retention only |
| Docker's embedded DNS on an internal network was not probed for tunnelling | Unverified; S7 |
| `indexed_at` and `embedded_at` are not cleared when a file later leaves the state | The ETA looks at two hours only |
| `buscador:throttle` has no effect on a single standard worker | Worker concurrency is out of scope; documented honestly |

## Claims that did not hold
None refuted. The reviewer's "doctor cannot see PHP-vs-PostgreSQL tzdata skew" is partly covered: it now checks the name against the database's own list.
