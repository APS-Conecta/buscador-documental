# S6 blueprint: UI (checkpoints answered at the start of implementation)

## Design
- **Backend additions (schema 5, `007_s6.sql`).** `file_meta.owner` (owner uid, filled by `FileIndexer` from `FileFacts.ownerUid`; files indexed before are queued once through the outbox like `ancestors`). Filters: `owner = mine|shared` (`m.owner = uid` / `IS DISTINCT FROM`) and `uncertain` (the chunk's page has `ocr_conf` below the threshold, default 60, setting `uncertain_below`). Hit gains `path` (relative to the caller's home, taken from the node the caller can read), `mtime`, `owner` (display name, null for team folders) and `uncertain`. All come from nodes already rechecked, nothing new is stored about people.
- **Page and admin API.** `PageController` (the search page, initial state: modes availability, thresholds, user page-size preference stored in the browser), `AdminController` (admin only, CSRF on): overview (status, doctor summary, ETA, scope rules, skipped files by reason with paging, profile summary), pause/resume, remove a scope rule ("Excluir"), retry a skipped file, acknowledge the first-run notice. Adding a folder to the scope stays with `occ` and the folder picker is a later enhancement; the panel says so.
- **Unified search provider.** Keyword only, top 5 (`limit` honoured), no model call, entries with title, `p. N`, one-line snippet and the file link; `getOrder` returns null when the index is paused or no folder is included.
- **Files tab "Texto reconocido".** A sidebar tab registered through `getSidebar().registerTab`; `GET /file/{id}/text` returns status, confidence and the text only when the caller can read the file, it is not excluded and the best node allows download; `POST /file/{id}/reread` for owner or admin, rate limited.
- **PDF page.** A spike decides at runtime whether the viewer can be sent to page N; if not, the card says "p. N" and the file opens at its first page with the page number shown in the sidebar.
- **Frontend.** Vue 3 + `@nextcloud/vue` 9 by subpath, Vite 7 with `@nextcloud/vite-config`, three entries, `js/` committed and checked for drift in CI. Components: `NcContent/NcAppNavigation/NcAppContent/NcAppSidebar`, `NcTextField`, `NcSelect`, `NcCheckboxRadioSwitch`, `NcListItem`, `NcChip`, `NcNoteCard`, `NcEmptyContent`, `NcDialog`, `NcSettingsSection`, `NcButton`; custom only for the pager and the highlighted snippet. State in the URL (query, mode, filters, order, page size, cursor). Spanish literals, usted, glossary terms, no internals in the text. The full state matrix of the mockup.
- **Tests.** vitest + jsdom + axe-core for every component and state; a Playwright run in a pinned image against the live stack for the keyboard-only path, 360 px with no horizontal scroll, `prefers-contrast: more` and reduced motion, real-browser axe on the search page, the admin page and the Files tab; a size gate on the built `main` chunk.

## Failure modes -> tests
| Failure | Test |
|---|---|
| Owner/uncertain filters leak or miscount | DB + Searcher tests, PG test with an unreadable file |
| Hit path/owner shown for a file the caller cannot read | recheck-based: fields built only from survivors; test with a revoked share |
| Admin endpoints reachable by a normal user, CSRF-less POST | controller tests + live check |
| Files tab shows text without download right or for an excluded file | endpoint tests (download-disabled share, tag, other user) |
| Unified search returns more than the limit or calls a model | provider test, `OutboundCallsTest` still green |
| Snippet markup injection | `v-html` only for a sanitised mark list; test with `<script>` and attribute payloads |
| Axe, keyboard, 360 px, contrast, reduced motion | vitest-axe per state + Playwright live |
| Bundle too big, committed bundle stale | size gate, drift check |
