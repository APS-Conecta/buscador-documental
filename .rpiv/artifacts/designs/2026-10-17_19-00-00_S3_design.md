# S3 design: events, reconciliation, scope and erasure

Status accepted (2026-10-17, human design review: verdict in `.rpiv/artifacts/verdicts/2026-10-17_19-30-00_S3_design-review.md`). Items marked **[YOUR CALL]** were decisions the docs do not settle; the value shown is the accepted one, except where the verdict says otherwise (trash, exclusion tag, first run). Verified facts only (the research claims were re-checked by a verifier and a live probe; corrections applied).

## 0. Principles
1. **Level-triggered.** An event is a hint "re-evaluate file X". The processor recomputes truth from `oc_filecache`, tags, shares and scope rules, so event order, loss and duplication cannot corrupt the index. Nightly reconciliation catches whatever never produced an event.
2. **Removal before addition.** Exclusion, scope exit and erasure are processed before any indexing, and are never held back by pause.
3. **Durable state in Postgres.** Jobs are triggers only (a `QueuedJob` disappears before it runs; a crashed `TimedJob` stays reserved 12 h). Job arguments never contain paths, names or uids (they are logged).
4. **Set-based in bulk, per-file only for the diff.** `FileFactsSource::load` is ~depth+3 queries per file; 1M files that way is an hour or more.
5. **Fail closed.** If scope, exclusion or tag state cannot be established, nothing is indexed and nothing new is served.

## 1. Data changes (`004_s3.sql`, `schema_meta.schema_ver` 1 -> 2; migration runs the schema step on enable like S1)
```
outbox(id bigserial pk, file_id bigint not null, kind text check in ('file','subtree','acl','rule'),
       created_at timestamptz default now(), processed_at timestamptz, attempts int default 0)
  unique partial index (file_id, kind) where processed_at is null     -- dedupe; ON CONFLICT DO NOTHING
  index (processed_at) for pruning (processed rows pruned after 7 days)
tombstone(file_id bigint pk, reason text, created_at timestamptz default now(), purge_after timestamptz)
audit_log(id bigserial pk, at timestamptz default now(), actor text, action text, subject_token text, detail jsonb)
  -- actor/subject are pseudonyms (below); detail never holds file names, paths, queries or document text
scope_rule(id bigserial pk, kind text check in ('folder','all_groupfolders'), file_id bigint, created_by_token text, created_at timestamptz)
reconcile_run(run_id bigserial pk, started_at, phase text, cursor_file_id bigint, rules_fp text, counts jsonb, finished_at)
settings(key text pk, value text)           -- scope_mode, paused, notice_ack_at, reconcile_window, audit_retention_days
purge_pending(token text pk, storage_numeric_id bigint, created_at)     -- deleted-user bookkeeping
pseudonym(uid text pk, token text unique, created_at)                  -- uid -> random token; the row is deleted when the user is erased
file_state: + acl_dirty_since timestamptz, + reconciled_at timestamptz;  partial index (acl_dirty_since) where acl_dirty
file_meta:  + storage_id bigint            -- written by FileIndexer::enqueue; erasure after user deletion and transfer detection
file_state.skip_reason: CHECK in (encrypted, too_large, corrupt, unsupported, ocr_failed, timeout, internal, unsafe,
                                  excluded, out_of_scope, trashed, user_deleted)
```
Functions (SECURITY DEFINER, owned by `bd_owner`, **not** granted to the worker): `erase_files(bigint[], text)` deleting `chunk`, `page`, `file_acl`, `file_meta`, `job` and every `chunk_vec_<gen>` (S4 creates those with `ON DELETE CASCADE` from `chunk`; the function also deletes by file_id from any that exist, so S3 tests need no rework) in one transaction per batch, lock order as `erase_file` (H1/H2); `purge_files(bigint[])` additionally deleting `file_state`. The existing `erase_file` stays as a wrapper. The worker gains exactly one more executable function, `schema_version()` (read-only), used for the start-up check (research C12); the privilege test "exactly four functions" becomes "exactly five".

## 2. Scope engine (U2)
- **Rules key on `fileid`.** A folder rule is a folder's `fileid`; `all_groupfolders` means every storage listed in `group_folders.storage_id`. Rules are independent of owner, mount and user view.
- **Predicate** `in_scope(file_id)`: the file is under `files/` (not `trash/` or `versions/`), its ancestor chain (as in `ExclusionChecker`) hits a rule root, or its storage is a groupfolder storage when the groupfolder rule is on, or `scope_mode = all_readable` (same predicate, rule set = everything; ADR-0006 "one scope filter"). `rag-excluded` on the file or any ancestor always wins. Bulk form: recursive CTE over `fs_parent` from rule roots (never `path LIKE` on PostgreSQL).
- **Moves.** A folder move fires one event for the root only; the processor treats `subtree` outbox rows by re-evaluating descendants in batches (in -> enqueue, out -> erase, within -> nothing).
- **Shares never change scope** (they change who may read, which is ACL).
- **Admin surface:** `occ buscador:scope:list|add|remove|preview|mode`. `add` takes a folder id or `<uid>:<path>`; `preview` prints counts (files, bytes, estimated hours) and nothing else; every change writes an audit row. Accepted: picker limited to what an admin can see plus groupfolders.
- `scope_mode = all_readable` is refused unless `settings.counsel_confirmed_at` and `settings.dpia_ref` exist (ADR-0006).
- **First run (decided 2026-10-17: index automatically):** the notice informs and does not gate. Under `opt_in`, indexing starts as soon as a scope rule exists; with no rule nothing is indexed (that is what `opt_in` means). `all_readable` stays locked until counsel and the DPIA are recorded (ADR-0006). `settings.notice_ack_at` is still recorded when an administrator acknowledges the notice, for the audit trail and the S6 screen.

## 3. Events and processor (U3)
- **Listeners** (all wrapped: never throw into the request, never block): `CacheEntryInsertedEvent`/`UpdatedEvent`/`RemovedEvent`/`CacheEntriesRemovedEvent` -> `outbox(file, 'file')`; folder `Updated` also -> `outbox(folder,'subtree')`; share created/updated/deleted (typed `ShareCreatedEvent`/`ShareDeletedEvent`, legacy hook for updates) and user/group membership events -> `outbox(...,'acl')` + `acl_dirty`; tag assign/unassign (`MapperEvent`) -> `outbox(...,'file'|'subtree')`; tag deletion (legacy string-keyed event) -> a `rule` row that re-evaluates exclusion globally; `BeforeUserDeletedEvent` -> record `purge_pending` only; `UserDeletedEvent` -> trigger erase. Events are hints: listeners store the file id and kind only.
- **`ProcessOutbox`** (a `TimedJob`, every minute, bounded batch, claims rows with `FOR UPDATE SKIP LOCKED`): for each row, in this order: (1) removals - gone from `oc_filecache` or trashed -> `erase`; excluded (file or ancestor) -> `erase`; out of scope -> `erase`; (2) if paused -> stop (removals above still ran); (3) in scope and readable -> `FileIndexer::enqueue` (idempotent on `(file_id, etag)`), principals recomputed only when `acl_dirty` or new; (4) mark processed. Failures increment `attempts`; after 5 the row is parked and counted in `occ status`.
- **ACL dirty** (decision): per-file `acl_dirty` + `acl_dirty_since`, marked in set-based batches of 5 000 by subtree for a folder share; processed ahead of backfill; backlog age = `now() - min(acl_dirty_since)` in `occ status`. Principals are written only when they differ (`IS DISTINCT FROM`) so `acl_ver` does not churn; the set-based recompute excludes expired user/group shares.
- **Groupfolder ACL/grant changes** have no typed event: a `GroupfolderPoll` timed job fingerprints `group_folders_groups` + ACL rules + `group_folders.acl` every 15 min and marks the folder's storage dirty when the fingerprint moves. Acceptable window = 15 min (the live recheck still protects reads).

## 4. Erasure and audit (U4)
- **`rag-excluded`** deletes chunks, pages, vectors, ACL and meta (`erase_files`), keeping a `file_state` row `skipped/excluded` so it is visible and not re-enqueued. Tag (decided: public): created *public and user-assignable* (visibility 1, assignable) so folder owners can opt a folder out, as the user page already says; admin-only is the alternative.
- **Trash (decided: erase at once):** on trash the index data is **erased immediately** (A-SEC-3 spirit); a tombstone with `purge_after = now + 30 days` records it; restore re-enqueues. **Correction (2026-10-17):** the dedupe in ADR-0005 is copy-on-hit from another file that is still indexed, not a persistent cache, so a restored file is read again in full unless an identical file is indexed elsewhere; the earlier remark that the cache makes restore cheap was wrong. The accepted decision stands (restores are rare; erasure at once is the safer default). Alternative: keep hidden for 30 days (cheaper restore, but index text of a trashed file lingers; counsel decides).
- **User deletion:** `BeforeUserDeletedEvent` records `purge_pending(token, home storage numeric id)` (it can be vetoed by another listener throwing, so no erase yet); `UserDeletedEvent` erases every `file_meta.storage_id = storage` row; core clears the user's filecache on the same event with an unspecified order, so erasure must not depend on filecache. The nightly reconcile erases residue (indexed files whose `oc_filecache` row is gone). Files the user shared into others' folders are not on the user's storage and are untouched.
- **`occ buscador:purge-user <uid>`** for an existing user: erases everything on their home storage and writes an audit row; for an already-deleted user: `--storage-id <n>` or the `purge_pending` token.
- **Audit pseudonymisation:** subject/actor are `token = random 128-bit` stored in the `pseudonym(uid, token)` table, which holds the uid only while the user exists; on erasure the mapping row is deleted, so audit rows become unlinkable (an HMAC would need a key stored in the same database). Retention 90 days (**counsel default**), pruned by the reconcile job. `detail` is a closed JSON schema (counts, reason codes, rule ids).

## 5. Reconciliation (U5)
`Reconcile` (`TimedJob` checking a local-time window, default 01:00-05:00, `settings.reconcile_window`) runs resumable passes keyed by `fileid` in chunks of 2 000-5 000 with the cursor in `reconcile_run` (a run older than 36 h is abandoned): (1) eligible set into an UNLOGGED `reconcile_node` table from the scope predicate; (2) forward diff -> outbox rows (missing, stale etag, `file_meta.storage_id` changed e.g. after `files:transfer-ownership`); (3) reverse diff -> erase (row gone, out of scope, excluded, trashed); (4) ACL drift: files under dirty or fingerprint-changed folders, full recompute weekly; (5) housekeeping: tombstones past `purge_after`, audit and outbox pruning, orphan jobs. Cap 50 000 outbox rows per night (backfill belongs to S5's throttle). `file_state.reconciled_at` + `skip_reason` give per-file status; counters in `reconcile_run.counts` feed `occ status`. Cost at 1M files is **unmeasured**; the plan adds an `EXPLAIN (ANALYZE, BUFFERS)` check on the seed and states the result honestly.

## 6. Pause, status and worker gate (U6)
- **Pause:** stops new claims (`claim_job` reads `settings.paused`) and byte serving (`ClaimGuard` refuses with 403), and stops *adding* work in `ProcessOutbox`; removals, exclusion and erasure always continue. In-flight leases end on their own (the worker abandons at its next fetch).
- `occ buscador:status` (queue depth, ACL backlog age, outbox parked, last reconcile counts, paused, notice), `pause`, `resume`, `reindex <file-id|--all>`.
- Worker start-up compares `schema_version()` with the version it supports and refuses to run on an unknown one.

## 7. Log hygiene (U7, A-SEC-5)
Scope is every log: Nextcloud, PHP, Apache access log (stdout), worker, parser, Postgres. Fixes first: `worker/main.py` and `parserd.py` log only reason codes and exception class names; `Job::start` argument logging is neutralised by never passing sensitive arguments; any app search endpoint is POST-only (Apache logs `%r` including GET query strings; recorded as a constraint for S4/S6). Canary: documents and queries carrying unique sentinel strings run through the whole pipeline, then every container's logs are searched; positive controls (a sentinel deliberately logged) must be *found* so the search cannot pass vacuously. Suspected sink to probe: Postgres `DETAIL: Failing row contains` through DBAL (unverified).

## 9. Failure modes -> tests
| Failure | Test |
|---|---|
| Lost events | truncate `outbox`, run `Reconcile`: missing indexed, edited re-queued, moved-out erased, deleted erased, drifted principals corrected (A-OPS-3) |
| Event storm / duplicates | 10 000 identical events -> one outbox row; processor idempotent |
| Crash mid-batch | kill the job between claim and mark: rows re-processed once, no duplicate chunks |
| Tag service or scope state unavailable | nothing indexed, removals still run, status `unavailable` |
| Erase vs in-flight worker | existing H1/H2 tests plus erase via `erase_files` |
| User deleted with no events | reconcile erases the residue; `purge_pending` path; audit row unlinkable after erasure (A-SEC-6) |
| Move into / out of an included subtree | live scope test (indexed / erased) |
| Pause | claim refused, bytes refused, removals still run |
| RBAC adversarial matrix | extends the canary: circle (x:recheck), groupfolder ACL/deny, expiry, download-disabled, multi-mount, moved, user deleted, stale index (A-SEC-1) |
| Log leak | sentinel canary with positive controls (A-SEC-5) |

## 10. Cost and risk
Seven units; U1 (schema) and U3/U5 (processor, reconcile) carry the risk. Reconcile cost at 1M files unmeasured; Talk/Deck/circle share events and legacy-jail groupfolders are untested live (their files rely on `x:recheck` and the live recheck, which stay authoritative). The counsel/DPIA gate (A-SEC-7) is unchanged: S3 delivers the mechanisms; any real-data install stays blocked until S7 records the legal gate.
