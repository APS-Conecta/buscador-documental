# S4 design: embedding profiles and hybrid search

## 0. Principles
- The permission model is untouched: stored principals prefilter every leg, the live recheck decides (ADR-0003). Nothing in S4 reads or writes Nextcloud permissions.
- Keyword search never depends on vectors, Ollama or the glossary build. Any failure on the semantic side degrades to Exacta with a visible notice; it never returns unrechecked rows and never fails closed on a model outage.
- Document text leaves the box only to the endpoint the admin configured. No text in logs (class + place only), no query text in logs or in the snapshot.
- The app ships no model. The admin pulls it in Ollama; the app records and verifies its digest.

## 1. Data changes (`005_s4.sql`, `schema_ver` 2 -> 3, idempotent like 004; `Version000003`; worker `SUPPORTED_SCHEMA = 3`)
- `embedding_profile(gen int PK, profile_id text, model text, digest text, dim int, quant text, query_prefix text, passage_prefix text, max_tokens int, state text CHECK (building|ready|active|retired), created_at)`; exactly one `active` row (partial unique index). Endpoint URL and token are not stored here (see section 5).
- `chunk_vec_<gen>(chunk_id bigint PRIMARY KEY REFERENCES chunk(chunk_id) ON DELETE CASCADE, file_id bigint NOT NULL, vec halfvec(<dim>) NOT NULL)` plus btree on `file_id`. Created by `aps_search.create_generation(profile ...)` (SECURITY DEFINER, owner `bd_owner`, name built with `format('%I')` from an integer). **The FK cascade fixes the orphan problem**: `write_result` deleting chunks removes their vectors in the same statement; `erase_files` keeps its explicit `file_id` delete as a second line. Plain table, so `erase_files`' `relkind='r'` loop covers it.
- HNSW (`m=16, ef_construction=64`) is built per generation by `build_index(gen)` only when the generation is `ready` (coverage reached) because bulk-load-then-build is 10x cheaper (S0). Before that, vector search uses the exact path.
- `file_state.vec_state` gets `CHECK (vec_state IN ('pending','embedding','embedded','skipped','failed'))` added NOT VALID, same pattern as `skip_reason`.
- `write_result` (CREATE OR REPLACE in 005) additionally sets `vec_state='pending'` and inserts a `vec` job with idem key `file_id:etag:gen` for the active generation (none if no active profile). `claim_job` and `fail_job` become lane-aware: the give-up step for lane `vec` sets `vec_state='failed'`, never `text_state`; the lease cap counts per lane (text 4 per worker, vec 2) so embedding cannot starve OCR.
- New worker-callable SECURITY DEFINER functions (search_path pinned, REVOKE FROM PUBLIC, GRANT bd_worker): `vec_profile()` (active gen, model, digest, dim, prefixes), `vec_chunks(job_id, lease_epoch, etag)` (returns `chunk_id, heading, text` of the claimed file; BD001 `stale_lease`/`etag_mismatch` as `write_result` does), `write_vectors(job_id, lease_epoch, etag, gen, chunk_ids bigint[], vectors text[])` (compare-and-set; rejects wrong dimension, non-finite values, a chunk id not belonging to the file, a retired gen; sets `vec_state='embedded'`; idempotent). `WorkerPrivilegeTest` function list grows by these three.
- `file_meta.ancestors bigint[]` (ids of parent folders up to the storage root, ids only, no names) + GIN; written by `FileIndexer` from `FileFactsSource` (a parent-chain walk on `oc_filecache`). A folder move already re-enqueues descendants through the S3 subtree expansion, which rewrites it; the reconciler's forward pass repairs misses. `mime_group` is computed in code from `mime` (pdf, word, sheet, slides, text, image) and filtered with `mime = ANY(:list)`; no column.
- `search_snapshot(qid uuid PK, uid_hash text, created_at, file_ids bigint[], chunk_ids bigint[], ver int)` UNLOGGED, pruned after 10 minutes by the existing housekeeping. Ids only, no text.
- `settings` keys: `semantic_enabled` (false until the eval gate passes, admin sets it), `semantic_min_coverage` (default 0.95, S0 gave no number; flagged), `embed_timeout_ms` (1500), `exact_scan_files` (2000).

## 2. Vec lane (U2, worker)
- `worker/embed.py`: Ollama client over `urllib` (no new dependency): `POST /api/embed` with `truncate:false`, `options.num_ctx=max_tokens`, `keep_alive:-1`, batches of 16, timeout scaled by batch, retries with backoff on 503/connection errors; verifies unit-ish norm and the profile dimension; checks `GET /api/tags` digest against `vec_profile().digest` once per claim and refuses with `model_mismatch` (job fails, generation not written) if different. Input text is `passage_prefix + (heading + "\n" if heading) + text`.
- `worker/main.py`: second loop step `claim_job('vec', ...)` after `text`; heartbeat and lease reuse; a vec job never fetches files from Nextcloud (it reads chunk text through `vec_chunks`). Parser sandbox is untouched; embedding runs in the supervisor `worker` container, which gets one new env pair `BD_EMBED_URL`, `BD_EMBED_TOKEN_FILE` and egress only to that host (compose documents it; the default stack points at the stub).
- Generation lifecycle (U5 command + housekeeping `VecBackfill`, respects pause): `profile set` creates gen N+1 (`building`), enqueues `vec` jobs for files with chunks in batches of 1 000 per tick; when coverage >= `semantic_min_coverage` the gen becomes `ready`, `build_index` runs, and the switch to `active` is explicit (`occ buscador:profile activate`) so a multi-hour re-embed never flips search by itself (ADR-0004 "never auto-switched"). Old generations stay until `profile drop <gen>`.
- Dedupe copy for vectors (ADR-0005) is deferred (cut): vectors are recomputed for identical content; recorded in the capacity sheet.

## 3. Query side (U4, PHP)
- `EmbedClient` (new, one implementation, no interface): `IClientService` with `['nextcloud'=>['allow_local_address'=>true]]` only for the configured host, validated by an `OutboundUrlValidator`-style check (http/https only, no userinfo, no redirects followed). Sends `query_prefix + query`; any error, timeout, wrong dimension or digest drift returns null. Never logs the text.
- `SearchRequest(query, mode exacta|significado|mixta, filters{types[], modified_from, modified_to, folder_id}, sort relevance|modified_desc|modified_asc|name_asc|name_desc, page_size 25|50|100, cursor)`; validation errors are 422 with Spanish messages. `Retrieve::run()` keeps its signature for the existing callers/tests and delegates to `search(SearchRequest)`.
- **Candidate set (one SQL per mode, both legs inside the same statement):**
  - Exacta leg: `websearch_to_tsquery(q) || websearch_to_tsquery(alt_i)...` (alternatives from the glossary, at most 5; tsquery `||` is OR, no operator strings are concatenated), principals prefilter and filters joined *before* the `ORDER BY chunk_id DESC LIMIT 10000` pre-limit, `ts_rank`, then best chunk per file (`DISTINCT ON file_id`), top **1 000** files. The OR relaxation runs only when the strict pass returns fewer than 25 files.
  - Vector leg: `SET LOCAL hnsw.iterative_scan='relaxed_order'; hnsw.max_scan_tuples=20000; hnsw.ef_search=200`; MATERIALIZED ANN CTE with the principals join and filters, re-sorted `ORDER BY d + 0`, best chunk per file, top 1 000 files. When the user can read fewer than `exact_scan_files` files (counted with `LIMIT n+1` on `file_acl`, after filters) or the generation has no HNSW index yet, the exact path (btree on `file_id`, then sort) is used.
  - Mixta fuses **at file level**: each leg yields a file rank (best chunk per file first), `score = sum 1/(60+rank)`; ties by `file_id`; the displayed chunk is the one from the better-ranked leg (keyword on ties).
- **Paging (A-FUNC-1/2):** page 1 of any query builds the ranked candidate list (<= 1 000 file ids and their chunk ids), applies the chosen sort to it in SQL (`mtime`, or a normalised `name_key = lower(unaccent(name))` with `COLLATE "C"`, `file_id` as final tie-break), stores it in `search_snapshot` and returns page 1. The cursor is opaque (`qid`, position, `ver`, HMAC with the instance secret, bound to `uid_hash`, 10-minute TTL). Later pages read positions from the snapshot; an expired snapshot returns `410 cursor_expired` and the client reruns page 1. Rechecks run per page with the existing refill loop reading further positions. `total` is the snapshot length, `capped` is true when 1 000 files were reached; "Mostrando a-b de N" tolerates N shrinking after drops.
- **Deviation from `01-architecture.md:64`:** date and name sorts are applied to the relevance-ranked top 1 000, not keyset over all matches. Reason: in the semantic modes every chunk "matches", so "all matches sorted by date" is meaningless; a position cursor on a frozen list gives no duplicates and no gaps by construction. The architecture text is updated; sorted views show the message "Se muestran los 1 000 resultados más relevantes".
- Snippets: keyword hits keep `ts_headline`; a semantic-only hit gets the first 35 words of the chunk (HTML-escaped, no `<mark>`). The etag guard from S3 still applies.
- Failure policy: query embed null -> Exacta plus `notice: "semantic_unavailable"` (Spanish text for the UI in the response); mode `significado` with no embedding returns Exacta results with the notice, never an empty list. `ExclusionUnavailable` keeps failing closed. Statement timeout keeps the "too_many" answer.
- Mode availability: `GET /search/modes` returns each mode as enabled or disabled with the reason (`coverage 62%`, `not validated`), derived from `semantic_enabled`, coverage and profile state. The controller route `POST /apps/buscador_documental/search` is new (OCS, CSRF-protected, `uid` from the session).

## 4. Glossary (U3)
- `tools/build_glossary.py` parses the supplied dictionary (`buscador/data/aps-glosario-chile.md`, to be saved from the user's text) into `app/lib/Search/glossary.json` `{version, entries:[{key, expansion, ambiguous}]}`: strips `$...$` fragments and parenthetical notes, splits `A / B` keys, normalises with the same fold as the index (lower + unaccent). A key is `ambiguous` when it occurs more than once after folding, is shorter than 2 characters, or is on a small hand-kept deny list (SS, CD, HD, FA, EA, CCR, CGR, PCR, TP, AM, OT, IRA, EC, DAS, AMP, ...). Ambiguous keys are never expanded.
- `Glossary::alternatives(query)`: for each unambiguous query token equal to a key, add the expansion phrase; for each expansion phrase found in the query, add the key. Result is plain strings handed to `websearch_to_tsquery`, capped at 5, order stable. Both directions, query time only: no reindex, no `ts_config_ver` bump, no files on the DB host.
- Tests: fixture of ~30 entries (acronym, reverse, accent, case, ambiguity, cap, injection-like input `& | ! <->` stays inert).

## 5. Configuration and operations (U5)
- Endpoint and token: app config (`embed_url`, `embed_token` sensitive) read by PHP; the worker gets the same values from its environment. `occ buscador:profile set <profile_id> --url=... [--token-file=...]` checks `/api/tags` for the model, records the digest, dimension (probe embedding) and prefixes into `embedding_profile`, audits (`profile.set`, no URL secrets), and starts the generation. `show`, `activate`, `drop`, `test` (measures embed throughput and prints the recommendation; works with Ollama absent: reports hardware only).
- `profiles.yaml` (shipped, versioned, `app/lib/Search/profiles.yaml`): `bge-m3` (ollama, tag `bge-m3:567m`, 1024-d, no prefixes, max_tokens 8192, batch 16, eligibility: measured >= X tokens/s and RAM) and `qwen3-embedding:0.6b` (query instruction template). The catalogue lists only models we have checked against a card; the admin may point at others with an override warning (ADR-0004).
- `occ buscador:status` gains `vectors: gen, profile, coverage %, state, backlog`. Preflight checks `vector` extension >= 0.8 (new check in `000_preflight.sql`, runs on schema 3 upgrade and names the admin step).
- `make eval-search` (U5): runs the real `Retrieve` (PHP, scripted nodes like `RetrievePgTest`) over `aps_search` on a corpus loaded from `spikes/s4/corpus` with a Spanish gold set of queries judged for lexical, paraphrase and acronym relevance; prints recall@10 for Exacta, Significado, Mixta, the filtered-recall delta (narrow user vs 200-group admin) and the head-term pre-limit effect. CI runs it with the stub embedder for plumbing only; the A-QUAL numbers come from a run with the real model (section 8).

## 7. Failure modes -> tests
| Failure | Test |
|---|---|
| Text re-index leaves stale vectors | DB: write_result on a file with vectors cascades them; vec job re-queued |
| Wrong dimension, NaN, foreign chunk id, retired gen in `write_vectors` | DB negative tests |
| Stale lease / etag change during embedding | DB + worker unit (as for `write_result`) |
| Model digest drift | worker unit: job fails with `model_mismatch`, nothing written |
| Embedding failure 5 times | DB: `vec_state='failed'`, `text_state` unchanged, other lane unaffected |
| Ollama down / slow / wrong dimension at query time | unit: Significado and Mixta return Exacta results plus notice; never empty because of the model |
| ACL: vector leg returns an id the user may not read | `RetrievePgTest`-style: stale principals reach recheck and are dropped in all three modes |
| Filters starve the pre-limit | DB: restrictive type/date/folder filter still returns matches beyond the newest 10 000 |
| Exact vs ANN path | DB: below threshold the exact path is used; recall 1.0 on a fixture |
| Paging: ties, expired cursor, tampered cursor, other user's cursor, permission revoked between pages | property test for A-FUNC-2 over 4 sorts: no duplicates, nothing readable-throughout skipped |
| Cap | 1 001 matches -> `capped` true, N = 1 000 |
| Glossary injection / ambiguity | unit, section 4 |
| Erasure with vectors (tag, trash, account deletion) | existing erasure live suite extended: `chunk_vec_<gen>` count is 0 |
| Log hygiene | `test-e2e-logs` extended with a sentinel in a query and in chunk text sent to the stub; stub records only that a call happened |
| Generation switch while searching | live: search works on the old gen during build; `activate` is atomic |

## 8. Cost, risk, open decisions
- Storage: 1024-d halfvec is 2 KB per chunk; the 3M-chunk reference corpus is about 6 GB of vectors plus about 8 GB of HNSW (S0 ratio 1.3x): added to `capacity-sheet.md` with the 384-d alternative.
- Ollama host for the real-model measurement is not decided. Options: (a) a `bd-ollama` container in our compose project pulling `bge-m3` (1.2 GB download, CPU only); (b) an endpoint you provide. CI never needs either (stub). I proceed with (a) for the measurement run unless you choose (b). The other Ollama on this VPS is not touched.
- Gold set judging: the A-QUAL-4 gold set (paraphrase and acronym relevance over Spanish text) needs a judge. Default: I draft 100 queries over the synthetic corpus plus public Spanish text, you review a sample.
- `semantic_min_coverage` 0.95 is my default; S0 left it unset.
- The glossary source text must be saved in the repo (it exists only in chat); until then tests use the fixture and the build script is exercised on it.
- Risks: filtered ANN recall for the narrow user (S0: about 0.81 on the ANN path) is covered by the exact-scan switch; real embeddings may move the crossover. Hybrid p95 at page 100 is unmeasured (S0 understated it): U4 measures it, with the per-page recheck cost the open item.
