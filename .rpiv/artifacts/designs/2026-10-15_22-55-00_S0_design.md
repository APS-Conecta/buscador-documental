# S0 design: throwaway-schema measurement harness

No slice map: the units below share one compose stack and one corpus, so they are sequential steps, not independent slices.

## 1. Shape
Workspace `/root/bd-spike` (local, not pushed). Only `capacity-sheet.md`, `[M0]` numbers in `acceptance.md`, the ADR-0001 outcome and the dev page return to `buscador/`. Schema `bd_spike`, never `aps_search`; nothing here is reused as final code (S1 owns the real schema, ADR-0002).

```
/root/bd-spike
  Makefile                 up | seed | corpus | load | measure | report | down | clean
  compose.yaml             project `bd-spike`, all binds 127.0.0.1
  db/Dockerfile            pgvector/pgvector:0.8.7-pg17-bookworm + unaccent, spanish_unaccent config
  worker/Dockerfile        python + tesseract-ocr-spa + ocrmypdf (version pinned and recorded)
  seed/seed_nc.sh          batched occ: users, 200 groups, groupfolders, ACL rules
  corpus/gen_corpus.py     synthetic Spanish corpus (Zipf), PDFs and images
  corpus/gen_vectors.py    random halfvec for latency
  corpus/gen_gold.py       200-query gold set
  bench/*.py               one script per measurement, JSON out
  results/                 raw JSON (not committed), summary.md
```

## 2. Stack (compose, project `bd-spike`)
| Service | Image / source | Notes |
|---|---|---|
| db | own build on `pgvector/pgvector:0.8.7-pg17-bookworm` | pin full tag. Sibling apps use pg18; the pgvector pg18 tag is not verified in research, so S0 uses pg17 and records the version in the sheet (see §8 flag). |
| nextcloud | `nextcloud:34.0.4-apache` (pinned like territorio) | `127.0.0.1:8190`, groupfolders enabled |
| worker | own build | `OMP_THREAD_LIMIT=1`, up to 8 processes |
Reuse farmacia pattern: `up -d --wait`, enable apps, restart nextcloud to clear APCu, wait again (`farmacia/Makefile:37-49`). Compose project and volumes prefixed `bd-`; `make clean` runs `down -v` on this project only. Never touch other containers.

## 3. Seed (`seed_nc.sh`)
Runs inside one `docker exec` loop, not one occ per user. Reuses `instalador/provisioning/lib.sh` patterns (group:add, user:add --password-from-env, group:adduser, groupfolders:create/group/scan, `groupfolders:permissions --enable` then per-path rules).
Fixtures:
- F1 `narrow`: user with 1 group, ~1-2 % of files readable.
- F2 `admin200`: user in 200 groups, ~all files readable.
- F3 groupfolder with nested advanced-ACL deny rules and `rag-excluded` tag ancestor, for the `isReadable` ancestor-walk test.
IDs are deterministic (seeded RNG); no dumps committed.

## 4. Corpus
- Generator emits per-file kind: native PDF, scanned PDF, photographed image (skew, noise, rotation), mixed PDF, PDF with fake/garbage text layer (visible and invisible).
- Terms Zipf-distributed over a Spanish vocabulary from a public Spanish corpus; head terms present in a large share of chunks. Document structure includes Artículo/Capítulo headings.
- Two scales: functional (~5-10k pages, real OCR end to end) and 1M-page equivalent (~3M chunks) loaded directly into `bd_spike` tables from synthetic text with **random halfvec** (latency only). Recall measured only on the functional scale with a real small embedder over the public corpus.
- `file_acl.principals` populated to match F1/F2 membership and group sizes.

## 5. Spike schema (`bd_spike`, throwaway)
`chunk(chunk_id, file_id, page, text, tsv generated via to_tsvector('spanish_unaccent', text) GIN)`, `chunk_vec(chunk_id, file_id, vec halfvec(384))` with HNSW built **after** bulk load, `file_acl(file_id, principals text[] GIN, acl_ver)`. Same column names as 01-architecture §2 so results transfer; no `ChunkRepository`, plain SQL in `bench/`.

## 7. Decision rules and outputs
- ADR-0001: confirmed iff keyword p95 < 1 s, hybrid p95 < 2 s, filtered recall within 5 points, RAM/disk fit minimum box (rule in `02-performance.md`). Otherwise write an OpenSearch ADR and stop; do not silently adjust thresholds.
- If m9 p95 > 300 ms: design the per-(uid, batch) readable-id cache or parent-folder batching and document it before S1 exits.
- Write `[M0]` values as numbers in `acceptance.md`; set caps (file size, pages, pixels, zip ratio, per-file timeout, xlsx rows) in `02-performance.md`.
- Fill `capacity-sheet.md` (template columns in `02-performance.md`), marking each value indicative; S4/S7 re-measure.
- Dev page (Spanish, in `docs-site/`): how to run the harness.

## 8. ADR conflicts and flags
- No ADR deviation. ADR-0001 is honoured as a baseline with a measured trigger.
- Flag: `02-performance.md` says `SET LOCAL hnsw.iterative_scan = relaxed_order`. pgvector README says relaxed results are out of order and need a materialized re-sort (`ORDER BY distance + 0` on PG17+); RRF depends on rank. m7 compares strict vs relaxed so the architecture text can be corrected from data.
- Flag: Postgres major. Siblings use 18, research verified pgvector images only for pg16/17. Pinned pg17 for S0; the minimum Postgres version in `info.xml` is decided from this.
- Flag: app id stays placeholder `buscador` (#6); real data re-run stays open (#2).

## 9. Failure modes of the harness
| Failure | Handling |
|---|---|
| Shared VPS contention skews timings | record load average and other containers' CPU in each result; repeat runs, report median and spread |
| occ seeding too slow for 200 groups | batch in one exec/PHP script; time it, cap fixtures if needed |
| Random vectors give unrealistic HNSW behaviour | label as latency-only; recall only from real embeddings on functional scale |
| OCR run hits `--tesseract-timeout` (180 s) or exit 6/8 | count as `skipped` with reason, not as failure; reported in m1 |
| `max_scan_tuples` returns short results | m8 records shortfall rate; not an error |
| Disk exhaustion at 3M chunks | check free space before load; abort cleanly; WAL volume logged |
| Stack leftovers | `make clean` removes only `bd-spike` project resources |

## 10. Test strategy
Spike code gets self-checks, not a test suite: generator determinism (same seed, same corpus hash), gold-set sanity (each query has at least one relevant doc readable by the intended user), seed verification via `groupfolders:permissions --test -u`, and an exact-scan baseline to validate recall computation. Dry run at the functional scale before the 3M load.
